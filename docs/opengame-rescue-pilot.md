# OpenGame 横版冒险实验

## 目标与当前范围

验证“稳定的玩法骨架 + AI 关卡/能力变化”是否比原来的 Collect 配置
生成更有吸引力。第一款样板是面向约 5 岁儿童、触屏优先的“小恐龙救朋友”。
这份实现尚未经过儿童试玩，不能把自动通关等同于好玩。

实现位于 `web/src/experiments/dino-rescue/`，有独立 HTML 入口、场景和
玩法契约，通过现有 Vite 服务与 React 外壳运行，不依赖 CollectScene。
本轮选择性提取 OpenGame 的行为基类和平台移动组件；没有复制完整战斗
模板、CLI 或自动进化模块，也没有加载影视题材的演示资产。

## 启动与访问

```bash
npm run dev
```

打开 `http://localhost:5173/experiments/dino-rescue/`，或从首页“新冒险”进入。
只试玩基础游戏和预设二段跳，也可运行 `npm run dev:rescue`，不需要后端。
实际 AI 修改使用现有 `server/.env` 中的 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL。

## 三个样板关卡

| 关卡 | 新变化 | 目标 |
| --- | --- | --- |
| 草莓小径 | 单格缺口，最后引入两格缺口 | 学会点击跳跃，到达下一站 |
| 会动的桥 | 在部分缺口上放置缓慢移动的桥 | 观察平台，跳跃通过 |
| 山洞里的朋友 | 山洞配色，组合此前机制 | 到达终点，找到兔子或小猫 |

恐龙自动前进；屏幕点击、下方跳跃按钮、空格和向上键均可跳跃。
二段跳开启后，空中允许再跳一次。草莓不是通关前提，避免因为漏捡奖励
卡住主线。旗子是检查点；跌落不扣生命，650ms 后就近重试，已捡草莓保留。
每关可以暂停、重新开始；页面失焦/隐藏时暂停正在进行的游戏。
声音来自用户交互后启动的 Web Audio，支持关闭，没有新增音频服务依赖。
角色动作是现有静态美术的轻微摆动与旋转，尚未制作专门的跑跳逐帧动画。

## 玩法契约

单一事实源：`shared/src/rescue.ts`；与原有 GameSpec 分开版本化。

固定项：自动前进、世界尺寸、重力、跳跃力量、移动速度、碰撞、重试、
素材资源路径与三个关卡的数量。模型不能生成 JavaScript 或改这些值。

可修改项：

- 游戏/关卡标题。
- `doubleJump` 和 `friend`（rabbit / cat）。
- 每关 `theme`（meadow / river / cave）。
- `gaps`：1–5 个缺口，start 为 9–54 格，width 为 1–2 格；bridge 控制桥。
- `checkpoints`：1–3 个，位置 5–56 格。
- `berries`：3–18 个，位置 4–59 格。

未知字段、超出边界的值、重复奖励/检查点、过密缺口，以及不安全的检查点
都会被拒绝。相邻缺口至少隔 6 格；检查点不能在缺口及边缘附近。
跳跃距离校验按固定物理参数做保守几何检查，并不是任意玩法的通关证明。
桥不作为通关必需条件：所有缺口仍保留普通单次跳跃的路径。

## AI 修改流程

`POST /api/rescue/modify`，请求为 `{ input, spec }`。

1. 校验孩子输入和当前配置。
2. 模型读取模板能力、当前配置与孩子要求，返回完整新配置。
3. 校验结构、缺口距离、落脚空间、检查点安全。
   同时按当前支持的中文请求词检查意图，拒绝未请求的角色、跳跃、主题、
   地形、奖励和检查点变化。此检查是保守规则，不是通用语义理解。
4. 校验失败时回喂具体错误，最多修正一次。
5. 成功后前端再次校验，然后创建新游戏，从第一关开始。
6. 网络错误/非法输出保留当前游戏，并明确提示失败；没有变化时说明未产生变化。

前端记录最近 10 次变化，可返回上一版或恢复样板。最新有效配置存于
localStorage；暂不保存当前关卡或通关进度。“预设二段跳”是本地确定性
试玩，界面明确标注，不伪装为 AI 生成。

## 对比用的孩子指令

| 指令 | 检查的实际变化 |
| --- | --- |
| 恐龙能跳两次 | doubleJump 为 true，实际空中只能额外跳一次 |
| 加一座会动的桥 | 新增 bridge=true 的缺口，正常碰撞与移动 |
| 朋友藏在山洞里 | 最后一关 theme=cave；若已经满足则允许不变化 |
| 少一点缺口，容易一点 | 缺口减少或变窄，仍然有可玩的关卡 |
| 把朋友换成小猫 | friend=cat，终点使用现有小猫素材 |

每个指令建议用同一份样板运行三次。记录成功/未变化/失败、耗时、意图是否
满足、能否操作与通关。暂不支持的飞行、武器等要求不应标成已实现。

## 验证与真人试玩

```bash
npm run type-check
npm run build
npm run test -w web
npm run test -w server
```

新增测试覆盖：危险地图拒绝、检查点安全、跳跃宽限、提前按键缓存、二段跳
次数、重试清理状态、模型错误修正、网络/非法输出保留旧游戏。
浏览器验收要覆盖：三关真实物理跳跃通关、跌落重试、暂停恢复、二段跳、
触屏布局、实际模型生成和版本恢复。保存的截图/验收记录位于 `artifacts/`。

随后让 2–3 个孩子在家长陪伴下试玩，尽量不先讲全部规则：

- 是否能理解跳跃与目标？需要多少次提示？
- 第一次卡在哪？就近重试是否容易理解？
- 是否主动再玩或主动提出修改想法？
- 生成变化以后，是否感知到差异、是否愿意继续玩？

“给家长”区域可导出当前配置与本次关卡事件，不上传试玩记录。
先据此调整跳跃、关卡节奏与反馈，再决定是否接 OpenGame 自由编码流程。

## 本轮验收记录（2026-10-13）

- 类型检查、生产构建、68 个单元测试全部通过。
- 浏览器用普通跳跃连续通过三个样板关卡，每关 0 次重试。
- 故意不跳，验证掉落后从检查点恢复；暂停后位置不继续变化。
- 实际点击验证二段跳；第三次空中输入不重置上升速度。
- 1024×768 触屏环境的跳跃按钮生效；390px 页面宽度无横向溢出。
- 预设二段跳、回到上一版，以及断网保留原玩法均经界面操作验证。
- 真实模型修改：二段跳约 10s、加桥约 21s、降低难度约 59s、换小猫约 9s。
  这是单次样本，不代表稳定延迟或成功率。
- 初次山洞请求意外把兔子换成小猫。补上意图检查后重新请求约 22s，
  保留兔子与原本已存在的山洞，返回“没有产生玩法变化”。
- 后端新增接口拒绝非法请求，返回 HTTP 400。

原始模型结果与修正后的山洞回归结果见 `artifacts/rescue-generation.json`；
三个屏幕尺寸截图同在 `artifacts/`。尚未验证儿童留存、iOS Safari 真机或
大量模型输出的稳定性。
