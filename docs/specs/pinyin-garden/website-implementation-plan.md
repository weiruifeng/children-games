# 首页与拼音花园网站化实施 Plan

日期：2026-11-08。依据：[网站化 Spec](website-account-cloud-save.md)，其中1.3节为已确认发布边界，第13节为最新数据设计修订。

状态：M0～M6本地实现与验证已完成，M7本地自动化/浏览器验收已执行；真实iPad、生产部署、独立备份和告警仍未验收。对应证据及容量实测见[验收记录](website-acceptance.md)。勾选表示本地交付，不代表已正式上线。原 `implementation-plan.md` 记录课程改造，本文件专门跟踪网站化。

## 1. 为什么需要独立 Plan

本次不是给前端加几个表单，而是首次建立用户身份、数据所有权、长期事件存储、离线队列和生产发布边界。仅依次实现Spec章节会遇到三类返工：

1. 数据模型决定API和前端存储；若先按全量Profile写接口，再拆学习事件，会重写同步、导出和清空逻辑。
2. 认证影响所有写接口、管理员初始化和前端加载；不能先把存档API公开再补鉴权。
3. 旧档迁移与内容发布共同决定可恢复性；只测新账号会漏掉真实用户升级后的数据损失。

实施采用串行里程碑，每个里程碑交付一条可验证链路。任务没有要求多代理；默认单执行者推进，避免多人同时修改GardenApp、共享契约和迁移。

## 2. 已确认边界与工作基线

- 正式产品保留当前LearningHome首页、Waji和拼音花园，新增账号/后台。首页不重定向掉。
- 游戏创造、模型调用、Studio、恐龙实验不上线；保留其源码和已有作品数据，不擅自删库。
- React/Phaser、NestJS/mysql2与共享TypeScript逻辑继续使用，不引入新游戏引擎或ORM。
- 已有文档修改与删除属于前序工作，不能reset或覆盖。编码前记录git差异；不用提交全部工作区代替隔离变更。
- 现有1342项前端/共享测试和24项后端测试的通过记录只属于此前基线，修改后重跑受影响检查。
- 本机已发现Node v24.14.0与MySQL命令行；这不代表测试数据库可用，需单独确认连接和建库权限。不得在真实用户库上运行清空型测试。
- 临时日志、截图、性能样本集中到 `.workbench/20261108-garden-website/`；正式代码、迁移、复用测试和部署工具不依赖该目录。现有Git忽略规则已覆盖它。

## 3. 先统一契约，避免边做边猜

M0必须把以下决定同步到Spec和共享类型，之后才建表和接UI。

| 问题 | 实施选择 |
| --- | --- |
| 学习历史是否长期保存 | 是；数据库事件不按45,000条截断，本地展示缓存可以有上限，但未确认outbox不能截断 |
| Profile与云DTO | 本地旧Profile.v3继续兼容；独立CloudProfileV1，去掉全量attempts与嵌套archive；checkpoint/waveStart内重复事件也必须抽离或以有界引用表示 |
| 数据版本 | 分别维护本地格式、云DTO、事件schema、content pack、revision、资源release |
| 三槽身份 | 每账号三个稳定profileId，API槽位1–3；内部索引0–2只在客户端适配 |
| 清空语义 | 清空游戏进度递增revision和progressGeneration；旧学习事件保留在旧generation，不进入新花园组题；删除历史是独立显式操作 |
| 事件身份 | 新事件一次生成eventId，重试不变；旧档导入用稳定的源指纹+序号/规范内容生成ID，保证重复导入去重 |
| 同步顺序 | 本地事务落盘事件和快照→确认所依赖事件批次→上传快照；旧快照响应不能清掉新本地修改 |
| 归档 | 原始迁移/冲突归档独立存储，不随热快照反复上传；读写均检查账号归属 |
| 历史聚合 | 固定账号报告时区，默认Asia/Shanghai；独立保留客户端发生时间与服务器接收时间 |
| 跨设备冲突 | 快照显式选本机/云端；双方已经持久化的合法学习事件不随选择删除 |
| 内容升级 | 只按已知版本迁移；失效战斗可归档后重新开始，合法长期成绩/历史仍可读取；未知损坏不自动清空 |
| 备份 | 有格式版本的分段导出/导入，分页取历史；校验上限与分段方式对称，不一次写入巨大localStorage |

容量在M0确定并形成常量：热快照字节上限、事件单条/每批数量及字节上限、归档分片大小、可接受总导入大小。使用已有合法大记录样本验证后确定；不得直接继承20 MiB为所有接口通用限制。运行时拒绝必须保留待上传数据并提供导出。

## 4. 里程碑与依赖

```text
M0 契约和测试基线
 → M1 独立构建/服务骨架/数据库迁移
 → M2 账号、邀请与后台
 → M3 云存档、事件、内容兼容API
 → M4 本地仓库与同步协调器
 → M5 接入游戏、旧档迁移与备份
 → M6 内容发布与运维交付
 → M7 全链路验收
```

M1即可验证首页和旧API隔离；M2可以验证管理员发码到普通用户注册；M3先用API验证数据，不等游戏UI；M4用确定性状态机测试；M5完成真实两设备闭环。M6完成后才能宣称有生产发布包。

### M3：云端快照、事件与版本兼容

- [x] 三槽摘要/读取/保存/清空接口，所有查询以当前session身份为作用域。
- [x] revision检查和mutationId幂等同事务；同ID不同正文拒绝，响应丢失重试不重复加版本。
- [x] 学习事件批量写入/分页查询/汇总，eventId稳定去重，记录generation和内容版本。
- [x] 明确迟到旧generation事件策略：保留旧历史但不作用于新进度；删除历史后用删除水位防止旧队列复活。
- [x] 快照校验包括levelStars键、有限字符串和嵌套集合；reject任意原始archive字段。
- [x] 私有迁移/冲突归档接口，限制分片/大小；日志不含正文、密码或令牌。
- [x] 发布内容版本注册及已知旧版本迁移；历史事件不依赖当前ENTRY_MAP仍存在。
- [x] 失效checkpoint单独恢复路径、对应提示与下载，不能catch所有错误就丢战斗。
- [x] 统计与近期组题证据查询，和现有readingFacts/planLesson保持语义一致。

验收：使用真实MySQL事务并发测试；两个账号不能互读；两设备竞争一个revision只有一方成功；事件重试不重复，清空后旧快照不能复活。

### M4：账号隔离的本地仓库与同步器

- [x] 保留旧saveStore作为迁移读取器，新建按userId/slot分区的IndexedDB仓库。
- [x] 同一事务保存热快照、事件outbox、dirty序列；发送前持久化冻结inFlight请求。
- [x] 单槽单请求，10秒周期合并常规修改，关键节点flush；无更新不发请求。
- [x] 网络超时按原mutationId/payload重试；已确认旧序列不能清理更晚dirty/outbox。
- [x] 401暂停并等待原账号重新登录；429按Retry-After；冲突/超大/未知版本不无限重试。
- [x] Web Locks与IndexedDB租约回退；锁释放、标签恢复和fencing检查。
- [x] 账户世代隔离：退出后迟到响应不得修改新账号UI，未确认数据不转移给其他账号。
- [x] 本机保存、云确认、错误、冲突状态分别上报；pagehide只作尽力同步。
- [x] 登录/重连先解决inFlight不确定结果，再判断拉取、上传或冲突。

验收：假时钟+可控网络覆盖响应丢失、乱序、断网、重试、切账号和多标签；浏览器关闭后重开可恢复outbox。无需依赖真实用户存档。

## 6. 上线前外部信息与继续推进规则

无需等待这些信息即可完成本地实现：域名/部署供应商、生产数据库地址、备份私有存储、告警接收方、管理员实际用户名、真实设备访问方式。

这些信息影响最终部署配置与验证，不影响账号/同步代码实现。准备模板与隔离环境演练后，再向用户索取实际缺失值；不猜生产密码、不替用户购买资源、不对未知线上数据库迁移。上线阶段只对已明确授权的目标执行。

如果数据库连接或依赖安装因环境权限失败，记录具体原因并使用规定的权限流程，不将集成测试改成mock后宣布通过。未提供外部环境时，可交付“本地可验收、待配置上线”的代码，但上线验收项保持未完成。
