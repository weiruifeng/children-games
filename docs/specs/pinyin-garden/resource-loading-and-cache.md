# 拼音花园资源加载、浏览器缓存与版本更新 Spec

- 状态：加载、缓存、更新及发布检查代码已落地；已完成本地自动化及 HTTPS IP 生产基础验收；真实 iPad Safari 设备矩阵待执行。
- 日期：2026-11-09。
- 适用范围：正式网站学习首页 `/`、拼音花园 `/garden/` 及其共享 Waji 素材；开发试玩入口复用资源加载能力。管理员页面不缓存账号或业务数据。
- 交付方式：本文所有功能与验收项组成一个完整交付范围，不划分首版、后续版或可选实施轮次。
- 关联：[网站与云存档 Spec](website-account-cloud-save.md)、[图片与动画规范](visual-assets.md)、[音频规范](audio-assets.md)、[部署手册](../../../deploy/garden-site/README.md)。

## 1. 问题、证据与目标

### 1.2 目标

- 首次访问、弱网、缓存清空和资源更新后，都不能进入缺图、空画板或必要读音缺失的学习环节。
- 页面先显示无需外部图片的加载反馈；只有当前目标环节的必需依赖就绪才放行。
- 资源按使用环节准备，支持后台预取全部已发布游戏素材，不把全部素材作为首页前置条件。
- 浏览器保留可复用资源，自动识别更新，只下载新增或变化的文件。
- 更新不中断正在进行的关卡，不混用不兼容的代码、课程和素材版本。
- 异常可解释、可重试、可退出；不通过清除存档或要求用户手动清缓存恢复游戏。

### 1.3 产品边界

- “本地一份”指用户浏览器中的公共资源缓存，不要求安装应用或手动管理文件。
- 服务端仍是资源发布源；仓库正式素材和生产发布产物均保留，缓存不是素材备份。
- 本方案包含资源缓存与断网提示，不新增离线认证、离线刷新后绕过登录或完整离线 PWA 安装能力。
- 保持现有规则：已打开且已经认证的会话可按现有存档机制断网续玩；刷新后仍需完成登录校验。当前关卡需要的素材缺失时不能离线进入。
- 资源更新不修改课程进度、学习事件、战斗规则和既有存档版本；课程或存档升级仍遵循对应契约。

## 2. 用户流程与加载位置

### 2.1 学习首页

HTML 立即提供纯色背景、站点文字和进入状态，不能依赖 Waji 图片或大尺寸背景显示加载器。JS 尚未启动时保留静态提示；模块加载失败后提供重新打开入口，禁用脚本时显示可理解的说明。

首页 Waji、当前可见图像解码完成后显示完整首页。等待时可以浏览已就绪文字；进入花园的动作可以打开花园加载页，但不能直接启动游戏。首页素材失败提供重试，不能留下破图或无说明的空白角色。

### 2.2 打开花园与选存档

认证、存档和公共页面素材分别显示真实状态：正在验证账号、正在打开存档、正在准备花园。账号失败进入账号流程；存档失败进入既有存档处理流程；素材失败进入资源重试流程，三者不互相冒充。

槽位页的 Waji、当前可见伙伴和背景就绪后开放槽位进入。打开某个存档后，目标花园首页依赖就绪再展示完整场景。允许返回学习首页和处理账号问题。

### 2.3 点击出发或直接访问关卡链接

1. 固定本次进入的发布版本、存档槽位、关卡、战斗难度及有效声音设置。
2. 解析本关完整依赖，优先读取已验证的本地缓存，补齐缺失资源。
3. 显示花园加载页，展示完成数量和当前准备步骤。
4. 解码图片、准备 Phaser 纹理和本关必要读音，创建游戏场景并完成首次有效绘制。
5. 所有必需条件就绪，显示完整战场和开始面板；此时才允许“开始第一波”。
6. 用户点击开始后才启动原有布置倒计时、敌人生成和判题流程。

URL 直达、浏览器前进后退、继续存档、失败重试、再挑战和下一关均经过相同入口。若实际依赖和场景仍有效，可立即复用；不得仅因为曾进入过此页面而跳过检查。

### 2.4 关卡内与退出

- 本关全部波次可能出现的角色、变体、损伤层、投射物、奖励和结算关键图片，均在进入时准备，不能等刷怪或结算才阻塞下载。
- 开始、继续、下一波、重试、拖放、拼卡及相关快捷键均检查就绪状态，不能只依靠遮罩拦截鼠标。
- 加载不消耗布置时间、不增加学习尝试次数、不记为答错或失败，不创建虚假的“已开始战斗”存档。
- 返回、设置、账号入口按当前页面需要保持可用；离开与保存继续使用现有串行保存及冲突处理机制。
- 隐藏页面、锁屏、切后台和恢复前台时先检查场景及资源状态；不自动恢复战斗或补算隐藏期间时间。

## 3. 资源清单与分组

### 3.1 资源覆盖

构建期扫描正式发布依赖，覆盖 JS/CSS、图片、CSS 背景、SVG 内嵌图片、Phaser 图片/图集、音乐、音效、读音及必要公共数据。当前使用系统字体，不为不存在的网络字体增加等待；以后新增字体必须声明替代字体及依赖级别。

所有游戏素材通过稳定逻辑 ID 解析，禁止页面继续散落写死原始素材 URL。包括当前 `Waji.tsx`、`PartnerIcon`、CSS 背景、铲子、露珠动画以及全部音频入口。历史文档、provenance、未引用候选图和旧实验资源不进入运行清单。

### 3.2 资源组

| 资源组 | 内容 | 放行条件 |
| --- | --- | --- |
| `site-shell` | 当前入口所需 JS/CSS、基础 SVG/代码图形 | 页面逻辑和无需图片的加载 UI 可用 |
| `learning-home` | 首页 Waji 与当前可见素材 | 首页完整展示 |
| `garden-shell` | 花园通用 Waji、槽位伙伴、通用图标 | 花园外壳完整展示 |
| `garden-home` | 花园首页背景、当前伙伴和入口素材 | 目标花园首页完整展示 |
| `battle:<levelId>:<battleStage>` | 当前关卡全部波次及结算必需图像、道具、数据 | 图片可用且战场首次绘制完成 |
| `speech:<levelId>` | 本关所有可能用到的目标字词与拼音读音 | 声音设置启用时，进入关卡前准备必要音频数据 |
| `collection:<page>` | 当前图鉴页可见伙伴及说明图 | 图鉴当前页完整展示；其他分页后台准备 |
| `optional-audio` | 背景音乐、一般音效 | 不阻塞开始；失败保留视觉反馈 |

资源组允许共享文件；逻辑 ID 相同或内容哈希相同的下载任务去重。分组由课程与战斗规则推导，不依靠手工维护一份容易漏项的首波列表。所有已发布资源组都纳入完整后台预取清单。

### 3.3 发布清单契约

构建输出不可变的 `/assets/garden/manifests/<releaseId>.json`。页面构建时固定该清单地址与 SHA-256，不在关卡中动态改用 latest 清单。另提供轻量 `/resource-release.json` 用于发现新版本；它不替换现有 `content-release.json` 的课程内容职责。

清单包含：

- `schemaVersion`、唯一 `releaseId`、`createdAt`、`appBuildId`、课程 `contentVersion` 和内容摘要。
- `resources`：逻辑 ID、同域哈希 URL、MIME、传输文件字节数、完整 SHA-256、类型；图像另含尺寸和估算解码字节数，图集声明图片与描述文件依赖。
- `groups`：资源组及依赖组、文件 ID、是否为当前入口必需、适用关卡/难度。
- `shellEntries`：首页与花园分别需要的入口 HTML 和完整 JS/CSS 依赖闭包；不包含后台业务页面或用户响应。

输出示例地址：`/assets/garden/files/plant_pod_slinger.<sha256>.webp`。格式转换后按最终文件字节计算哈希，PNG 等原格式可按适配规则保留；格式备选必须在加载前选定，禁止同一逻辑 ID 无界重复尝试。

`resource-release.json` 只包含最新发布 ID、清单地址/摘要及必要兼容元信息。首次进入必须使用本页面固定清单；发现新版本只形成更新提示。

构建检查：逻辑 ID 唯一、依赖无环、所有正式引用可解析、文件存在且摘要/尺寸一致、课程和战斗可达资源覆盖完整、发布白名单无旧实验依赖。清单本身不能循环计算自身摘要。

## 4. 就绪模型与运行协调

### 4.1 分开管理的状态

单资源状态：`idle → queued → fetching → verifying → preparing → ready`，异常为 `failed`，取消为 `cancelled`。

进入任务状态：`resolving → loading → preparing-scene → ready`，另有 `failed` 与 `cancelled`。缓存持久化为独立的 `stored / memory-only / unavailable` 状态；持久化失败不把已准备好的游戏判成不可玩。

- 图片 ready：取得正确文件并验证，解码成功，宽高有效；Phaser 使用的纹理已注册。
- 场景 ready：宿主有有效尺寸、关键对象已创建、依赖纹理存在，并完成包含背景和棋盘的首次渲染。仅存在 `<canvas>` 或触发 `create()` 不足以宣告完成。
- 音频数据 ready：已取得正确数据；在已解锁 AudioContext 中解码完成，或等待用户手势后完成解码。浏览器播放权限另行记录为 `locked / unlocked / unavailable`。
- 进入 ready：当前必需资源均 ready，场景就绪，认证/存档满足既有条件；启用读音时满足第 5 节要求。

Loader 的 complete 事件即使伴随失败文件也不能作为唯一放行条件。场景创建异常、零尺寸宿主或首次绘制失败均进入错误状态。

### 4.2 ResourceManager 与 Phaser/React 桥接

统一 ResourceManager 负责清单、依赖、缓存验证、并发、取消、重试、进度和引用计数，供 React、Phaser、音频共用。建议接口：

```ts
prepareGroup(groupId, { signal, priority, releaseId }): Promise<PreparedGroup>
subscribe(taskId, listener): () => void
acquireImage(resourceId): Promise<ImageHandle>
acquireAudio(resourceId): Promise<AudioHandle>
release(handle): void
retry(taskId): Promise<PreparedGroup>
```

- 同一 URL/哈希只存在一个进行中的文件获取任务；多个消费者共享结果。取消一个消费者仅释放其引用，不中止其他消费者仍在使用的下载。
- 首次未被 Service Worker 控制的页面也使用同一 ResourceManager，不等待 Worker 激活才加载图片。
- 首次获取的数据可通过共享解码对象或 Blob URL 提供给 DOM、SVG、CSS 与 Phaser，避免浏览器图片请求和 Phaser XHR 重复下载同一文件。Blob URL 仅在全部消费者释放后撤销。
- Phaser 桥提供进度、场景就绪、失败及销毁通知；React 不能用“没有收到错误”推断成功。
- 任务使用唯一 generation，绑定页面、槽位、关卡、难度和版本；回调只影响当前 generation。重试、切关、退出、卸载后，过期回调不得更新新场景。
- 游戏推进与输入入口统一读取 `entryReady`，作为独立于手动暂停、引导、设置和云冲突的冻结原因。移除某一冻结原因不能清掉其他原因。
- 失败重试保持当前待开始/待继续状态与快照，不重新调用 startWave，不重建用户进度，不重复提交学习事件。

### 4.3 真实进度

主要展示“正在准备花园 · 已完成 N/M”，N 为本任务已验证并准备好的必需文件数量；缓存读取与解码同样计入实际任务，失败项不算成功。

进度条按完成数量单调前进；资源分母在依赖解析完成后固定。网络字节进度仅作为辅助，不把跨域未知 Content-Length 或压缩传输强行换算成精确下载百分比。文件完成后进入“正在铺好小路…”的场景准备状态；场景就绪才显示最终完成标记。

不按定时器模拟进度，不用固定等待秒数代替就绪，不在最后一个文件到达时提前宣布可以玩。后台预取与版本下载不计入当前关卡进度，不能让进度倒退。

## 5. 音频与学习正确性

- 用户出发手势中同步调用已有音频解锁，不能等异步下载结束后才请求解锁。下载、解码、播放权限分别记录；音乐失败不能冒充图片失败。
- 启用朗读且音量大于零时，本关必要读音必须下载并准备；缺失时提示“有几段读音还没准备好”，提供重试和返回。通用 UI 音、背景音乐失败不阻塞。
- AudioContext 被系统挂起或首次未解锁时提供“点一下开启声音”，保持待开始；用户手势后完成必要解码。不得为了进度到 100% 自动播放，也不得强制开启用户关闭的声音。
- 用户可以在设置中明确关闭朗读，以适用于纯视觉操作的既有玩法继续；若课程存在依赖听音才能理解/作答的任务，该任务必须保持阻塞，不能通过关闭声音绕过。
- 静音/关闭朗读时不把必要读音作为当前视觉关卡前置条件。关卡中重新开启朗读须暂停，补齐本关读音并完成解锁后，由用户点击继续；下载失败允许再次关闭或返回。
- 播放中断、输出设备切换、解码失败时保留文字目标，不计错答。必要读音不可用则暂停相关学习流程并重试，不使用未经审核的合成读音替代。
- 后台音效下载的失败重试不能在很久后补放过时的攻击或奖励声音；保持现有事件时效控制。

## 6. 本地缓存与后台预取

### 6.1 三层职责

| 层次 | 保存内容 | 生命周期与用途 |
| --- | --- | --- |
| 运行内存 | 解码图像、Phaser 纹理、AudioBuffer、Blob URL、共享 Promise | 当前页面按引用计数复用；离开不再需要的关卡后释放 |
| HTTP 缓存 | 带哈希的公开响应 | 由浏览器和响应头管理，减少传输；不能假设永久存在 |
| Cache Storage | 验证过的公共资源和公开应用外壳 | 应用管理命中、版本引用与清理；配合 Service Worker，失败可退回内存/网络 |

资源索引使用独立 IndexedDB 数据库 `garden-resource-cache`，保存资源摘要、字节数、最后访问、发布版本引用、完整状态和当前客户端租约。与玩家存档库、账号会话及恢复日志物理分开，不修改其版本或清理其对象仓库。

缓存命名带项目命名空间与缓存协议版本，例如 `garden-resources-v1`、`garden-shell-v1`。按内容哈希跨发布共享文件，不能每次发布复制整套素材。

### 6.2 获取与校验

1. 用当前固定清单解析文件，优先检查已验证缓存。
2. 首次读取持久缓存的文件时核对字节数及 SHA-256；同一页面内已验证且仍持有的对象复用验证结果。损坏文件仅移除该资源条目，重新获取。
3. 未命中则发起可取消请求，检查 HTTP 状态、MIME、最终大小和摘要。404 HTML、空文件、截断文件、解码失败或哈希不匹配均不得写为成功。
4. 完整验证后再发布可读取缓存条目；缓存写入和索引更新中断可以留下孤立文件，但不能留下虚假的 ready 索引。启动时可修复索引，查不到实际文件视为未命中。
5. 持久化失败但数据已取得并准备成功，当前环节继续；设置页提示“本次可以玩，下次可能需要重新下载”。禁止无限写入重试。

正式默认同域资源。继续支持资源基地址配置时，CDN 必须提供 CORS 可读响应、允许摘要校验，具有不可变路径和一致 MIME；不接收 opaque 响应。凭据不随公共资源发往第三方，发布检查必须验证允许的源与响应头。CDN 不满足要求则部署同域资源，不静默跳过校验。

### 6.3 调度与预取

- 总文件获取并发默认 4，后台预取最多占 1 个名额；当前进入任务优先。图片大文件解码和音频解码分别限制并发，默认各 1，避免手机瞬时内存峰值。
- 当前环节稳定就绪且页面可见后，先预取相邻关卡/当前图鉴，再逐步覆盖清单内全部已发布素材；素材已缓存且验证通过即跳过。
- 下载优先级变化时停止或让出后台任务；已共享给前台的请求不得误取消。网络变慢、进入关卡或隐藏页面时暂停纯后台预取。
- 浏览器报告省流量或慢速连接时暂停自动后台预取，只获取当前环节必需资源；无法获取网络质量信息时采用保守并发。
- 家长设置提供“缓存全部游戏素材”，展示真实文件数与剩余估计体积，并允许暂停、继续。在省流量环境下仅用户明确点击才开始全量预取。
- 完整素材缓存只代表相应发布素材齐全，不代表账号认证、API、存档同步或离线刷新可用；文案必须说明这一边界。

### 6.4 容量与清理

- 应用资源持久缓存默认预算 150 MiB，计入全部资源与已保存外壳；运行内存另计。可用存储估计不足时进一步降低实际预算，不能把固定预算当作设备保证。
- 优先清理无人使用的旧资源、旧发布外壳和低优先级预取；当前关卡必需文件不得为下载未来关卡而被应用主动清理。
- 无法清出足够空间则停止预取，按需网络加载，当前游戏不因“写不进缓存”而失败。浏览器驱逐仍可能发生，实际读取始终检查文件存在。
- 家长资源管理显示版本、已缓存/全部数量、应用可统计缓存字节数、持久化状态和上次检查时间；提供“检查更新”“缓存全部游戏素材”“清理素材缓存”。不将浏览器总占用冒充素材精确占用。
- “清理素材缓存”明确说明不删除存档；游戏进行中先提示回花园再清理。跨标签页存在活跃关卡时仅清理未使用资源，并说明使用中的资源会保留。
- 清理不调用全站存储清空，不移除玩家 IndexedDB、localStorage 恢复记录、Cookie 或其他应用缓存。退出账号清理用户运行态，公共资源允许保留并跨账号复用。

## 7. Service Worker 与降级

- 生产 HTTPS 为 `/garden/` 注册稳定地址 `/garden/sw.js`，作用域限定 `/garden/`。Worker 响应每次校验更新；不要使用每次发布不同脚本 URL 导致长期失去更新入口。
- Worker 缓存并提供 `/garden/` 的公开外壳及其明确列出的静态依赖，读取 ResourceManager 已验证的内容缓存；不拦截缓存认证和业务 API。根首页通过 ResourceManager/HTTP 缓存复用素材，不扩大 Worker 作用域到管理后台。
- 安装 Worker 只准备最小引导，不一次性预缓存所有图片/读音；首次访问与注册失败都不阻塞游戏资源加载。
- 已保存外壳必须包含同一构建的 HTML、JS/CSS 完整依赖和固定资源清单，全部验证成功后才提交完整标记。不能用某版本 HTML 配另一版本 JS。
- 在线导航优先检查服务端入口；网络失败可返回完整的公共外壳，由应用正常处理登录失败/断网。它不能使用缓存 `/me` 判断登录，也不能复原上个账号的画面。
- Worker 更新等待安全切换，不在战斗中 `skipWaiting` 后强制刷新；默认不抢占现有页面。用户在花园安全位置明确更新后才激活并重载；多标签页不强制替其他页面刷新。
- 新 Worker 兼容仍活跃页面的缓存协议，不在 activate 时一律删除旧缓存。协议不兼容时保留旧命名空间，待旧客户端退出后清理。
- 不支持 Service Worker、Cache Storage 或持久化被禁用时，使用同一 ResourceManager 通过网络与内存加载，保留就绪检查、进度和重试。明确提示缓存不可用，不把整个游戏判为不支持。
- CSP 需支持正式静态源及实际使用的 Blob 图像/音频，不为此开放任意脚本源；哈希校验使用 Web Crypto，正式 HTTPS 与 localhost 开发分别验证。

## 8. 资源更新与版本一致性

### 8.1 版本固定

区分应用构建 `appBuildId`、资源发布 `releaseId`、课程 `contentVersion`、清单/缓存协议 `schemaVersion`。资源版本变化不得强行改写玩家存档中的内容版本。

本标签页初始页面固定一份与代码兼容的资源发布；一个关卡始终固定同一发布快照。运行中检查到 latest 变化，不直接改 URL 或替换 Phaser 纹理。

### 8.2 自动检查与更新体验

- 页面就绪后后台检查 latest；回到花园及前台恢复时可检查，间隔至少 5 分钟。家长主动点击检查不受此节流限制。
- 无变化不打扰；有变化时后台验证新清单，按哈希复用相同文件，仅获取新增/变化依赖，遵守省流量、容量与前台优先规则。
- 新清单未知协议、代码不兼容或文件未发布完整时，不标记更新可用，不破坏当前版本。
- 花园内显示轻量“花园有更新，准备好后可重新打开”；战斗中不遮挡题目，更新入口放设置。更新失败只影响新版本准备，不影响当前可用版本。
- 用户选择更新时，先暂停并完成本地快照及现有必要保存流程；保存失败保留页面并提供既有重试/备份处理，不自动重载。云端未同步状态须保留在本地队列并遵循现有账号策略。
- 页面重载后新代码使用自己的固定清单；即使后台预取未完成，新页面仍通过加载流程补齐必需依赖，不宣称全量更新完成。
- 更新不能把旧素材当新素材使用；可保留旧版继续当前关卡，但不得把旧哈希内容返回给新哈希 URL。

### 8.3 多标签页与保留

客户端通过独立资源协调通道登记发布版本与活跃资源引用，不复用玩家存档写锁。可用 BroadcastChannel 与 Worker clients 协调；不支持时保守保留资源并依赖实际检查。

前台每 60 秒更新一次资源租约，后台页面仍由 Worker 可见客户端列表保护；客户端消失或连续 24 小时无法确认其存在的租约可视为过期。恢复旧页面时重新检查资源，不假设租约仍有效。

本地保留当前使用版本及最近一个完整可用旧版本；活跃客户端引用优先于清理和预算。容量不足时宁可停止预取，也不主动破坏当前运行。崩溃遗留引用可回收，不无限积累版本。

服务端旧文件至少保留 30 天，并覆盖已知仍受支持的客户端版本；30 天是最低保留窗口，不代表可删除仍在支持范围内的文件。超出支持期的页面显示保存后更新提示；不能静默请求另一套素材。资源保留不能替代前后端接口兼容。

### 8.4 兼容与回滚

- 发布记录声明支持的应用构建、课程和 API 契约范围。纯素材变化复用现有业务接口；课程/接口不兼容变更必须按现有内容迁移与服务端兼容规则单独校验。
- 部署切换 latest 不改变旧清单及哈希文件；回滚时切回匹配的代码、资源清单及兼容后端，不只修改一个资源版本号。
- 新版本准备失败保留当前完整版本；没有完整旧版本时展示重试/返回，不拼接半套新旧资源。
- 回滚不执行玩家数据清空，不以删除资源缓存解决存档版本不兼容。

## 9. 失败恢复与错误分类

| 情况 | 用户反馈 | 系统处理 |
| --- | --- | --- |
| 下载慢但仍推进 | “正在准备花园 · N/M” | 保持加载，不伪造成功 |
| 必需下载长时间无进展 | “网络有些慢，可以重试或回花园” | 有限超时、保留已完成项 |
| 断网且必需素材缺失 | “这次还缺几张图片，联网后再试试” | 不进入玩法；已缓存完整依赖可继续准备 |
| 404、MIME 错误、摘要不符 | “有些素材暂时打不开” | 排除该条缓存、有限重新获取并记录发布错误 |
| 图片/音频解码失败 | 指出图片或读音未准备好 | 校验并重取一次；仍失败进入人工重试态 |
| 场景异常或画布不可用 | “小路还没准备好，请重新打开战场” | 销毁失败实例，复用成功文件重新创建 |
| 缓存存储不可用/空间不足 | 设置中提示缓存不可用 | 内存/网络继续；停止后台预取 |
| 普通音乐音效失败 | 设置中轻量提示 | 保持玩法，允许重试，不补放过期事件 |
| 认证/存档错误 | 现有账号或存档提示 | 不当作素材错误重试，不清理玩家数据 |
| 新版本准备失败 | “更新还没准备好，当前花园可以继续” | 保留旧版与当前关卡 |

默认网络策略：单次请求 20 秒无数据进展或总计 60 秒触发超时；只在有可观测字节进度时重置无进展计时。缓存读取/校验/解码与场景准备也有超时保护，不允许无限转圈；前台场景创建与首次绘制默认 10 秒，后台挂起不计入有效前台时间。

瞬时网络异常、超时、408、429、5xx 自动最多重试 2 次，采用约 1 秒、3 秒退避并带抖动，429 尊重合理 Retry-After。离线暂停自动重试，恢复联网后可重试当前未取消任务；不自动启动战斗。

404、未知清单协议、持续摘要不符不进入无限退避。自动重试耗尽后提供显式重试与返回，保持已经成功的依赖。用户每次重试有独立尝试记录，连续点击去重。读取缓存损坏时只绕过对应缓存，必要时对同一哈希 URL 发起强制重新验证请求。

WebGL 上下文丢失立即冻结玩法并保留快照，恢复后重新检查纹理和首次绘制；无法恢复时允许重建或返回。不以“资源文件缓存完整”掩盖渲染故障。

## 10. 视觉、动画与无障碍

### 10.1 加载页

沿用纸艺花园的米白底、苔绿、嫩叶色和圆角边框。加载器由 HTML/CSS/内联 SVG 实现，不依赖尚未加载的位图；Waji 资源成功后可以加入现有轻量待机反馈，不能为了显示加载器再等待角色。

固定结构：标题“正在准备小花园”、当前步骤、真实进度条与 N/M、网络较慢或异常说明、当前可用操作。进度条与数字不能挤压拼音文字或遮挡账号/存档异常提示。缓存快速命中时直接进入，不人为保留加载页。

### 10.2 必须交付的动画反馈

| 操作/状态 | 动画 | 结束与重复行为 | 减少动态模式 |
| --- | --- | --- | --- |
| 实际进度增加 | 进度填充约 120–180ms 平滑过渡 | 每次只向真实新值前进，不循环假进度 | 即时更新长度及数字 |
| 场景准备成功 | 直接展示就绪页面，不对整页重新播放淡入 | 不延迟操作，不因刷新重复进场；游戏内既有反馈继续保留 | 相同的即时切换 |
| 加载失败 | 提示区短淡入与状态颜色变化 | 不抖屏、不闪烁；重复失败不叠动画 | 即时显示图标和文字 |
| 点击重试/返回/缓存操作 | 复用现有按钮按压反馈 | 禁止重复提交，结束恢复正常状态 | 即时按压颜色变化 |
| 后台缓存完成 | 设置页内一次完成标记 | 不弹出遮挡游戏的庆祝层 | 静态勾与说明 |

尊重游戏内“减少动态”和系统 `prefers-reduced-motion`，任一启用即简化；存档设置尚未读取时先尊重系统设置。动画完成事件不得作为资源 ready 或战斗启动条件，不改变既有判题与战斗时序。

### 10.3 可访问性与触屏

- 加载区域使用语义化进度和 `aria-busy`；读屏播报步骤、失败和完成，不逐字节播报。
- 全屏等待时管理焦点，不能 Tab 到尚未开放的开始按钮；完成后焦点落在当前主要操作，取消/返回后恢复到合理入口。
- 按钮触控目标至少 44×44 CSS px；支持键盘、触屏和鼠标。
- 390px 窄屏、iPad 横竖屏、浏览器缩放及安全区域不溢出；旋转后重新确认画板尺寸，不重复下载成功资源。
- 无动画时仍能理解加载、成功、失败、重试及缓存状态；不使用强烈闪烁或持续装饰粒子。

## 11. 构建、体积与运行性能

### 11.1 素材处理

生产构建生成运行素材衍生版本和哈希地址，原始授权素材及制作源文件按现有规范保留。透明角色优先使用经过目标浏览器验证的 WebP 或合适 PNG，背景按实际显示需求缩放压缩；不得损伤拼音、文字、透明边缘、角色锚点或动画对齐。

清理发布依赖中的未使用大图和重复变体，不删除仓库原始素材。不得在本次资源改造中擅自更换美术身份或为减小文件移除必要状态。

### 11.2 预算与可测指标

作为本方案默认发布门槛，按构建最终文件的去重字节统计：

- `learning-home` 首次可见位图资源不超过 4 MiB。
- 任一关卡的必需图像、读音及其通用素材闭包不超过 12 MiB；音乐与后台预取不得混入前置闭包。
- 单关同时持有图像的估算 RGBA 解码总量不超过 96 MiB；该估计不代表浏览器或 GPU 总内存，需另做真实设备观察。
- 同一哈希文件的并发网络获取为 1；跨 DOM/Phaser 的复用必须实际验证。
- 在可见页面中，全部必需资源已准备到首次绘制就绪不超过 2 秒，参考验收设备为真实 iPad Safari 和桌面 Chromium；每种设备分别记录，不用桌面结果代替平板。
- 缓存命中后仍可有清单检查和校验开销；不得把网络请求总数为零作为命中标准。必需素材不应再次传输完整响应体。
- 连续进入/退出关卡 20 次后，Phaser 实例、事件订阅、Blob URL 和不再使用的解码对象回到稳定基线，不随次数持续增长。

构建报告列出每个资源组的字节数、重复资源、最大文件及估算解码量，超预算阻止发布。真实设备性能不达标时修复资源/解码/调度问题，不能通过隐藏加载页或提前放行满足指标。

## 12. 发布、校验与回滚流程

一次发布包含匹配的页面代码、Worker、不可变资源清单、哈希素材和版本指针；统一进入正式网站专用构建与发布检查。

1. 构建生成哈希素材、依赖组、清单与体积报告，运行覆盖与摘要检查。
2. 先上传所有新哈希文件和不可变清单，旧文件保留。
3. 对实际生产源/CDN 检查文件、状态码、MIME、CORS、响应头和字节摘要，不能只检查本地构建目录。
4. 验证匹配的 API/课程兼容，部署页面与 Worker；入口通过版本目录原子切换，避免发布过程中 HTML/JS 混用。
5. 入口可用后更新 `resource-release.json`，发布指针只能指向已经完整部署的版本。
6. 在生产入口执行冷缓存、热缓存和旧页面保持打开的冒烟验证，再记录发布成功。
7. 故障时回切匹配代码/清单/兼容后端，更新 latest 指针，保留新旧不可变文件供已有页面使用；检查玩家保存与恢复。

HTTP 缓存契约：

| 路径类型 | 策略 |
| --- | --- |
| 入口 HTML、`resource-release.json`、既有 `content-release.json` | `Cache-Control: no-cache`，允许 ETag 校验 |
| `/garden/sw.js` | `Cache-Control: no-cache`，稳定脚本地址，确保更新检查 |
| 带内容哈希的 JS/CSS/图片/音频及不可变清单 | `public, max-age=31536000, immutable` |
| 认证、账号、云存档及管理业务 API | `no-store`，禁止进入资源缓存 |
| 静态资源不存在/失败响应 | 不长期缓存，必须是真实错误状态；不得 SPA 回退到 HTML |

路径包含 releaseId 的清单只有在该 ID 永不覆盖时才能视为 immutable。CDN 清理/回源规则遵循同一协议；资源更新靠新地址，不依赖全站 purge 或用户手动清缓存。

## 13. 可观测性与资源诊断

记录可区分的阶段耗时：清单解析、缓存读取、下载、校验、解码、场景创建、首次绘制及总进入耗时；记录命中来源、失败分类、重试次数、版本、逻辑资源 ID 和设备浏览器类别。

- 家长设置提供只读“资源状态”，可查看当前发布、当前组完成情况、缓存能力与失败摘要，并导出不含个人信息的诊断 JSON。
- 诊断不包含账号密码、Cookie、签名 URL、玩家姓名、存档正文或学习事件；资源错误不复用存档错误提示。
- 接入现有错误采集能力；如当前没有集中采集，提供有界本地诊断环形记录和导出，不为本方案新增第三方追踪服务。
- 本地记录最多保留最近 100 条任务摘要，单次错误相同资源去重，避免长时间玩游戏写满日志。
- 发布验收报告记录真实性能和失败率；线上资源 404、摘要不符及关卡无法就绪应可按 releaseId 定位，不能只留下“加载失败”。

## 14. 验收矩阵

以下均为完整交付必须通过的验收；浏览器自动化使用隔离账号/存档，网络故障通过可控拦截注入，不在生产账号上制造失败。

| 编号 | 场景 | 必须验证 |
| --- | --- | --- |
| A01 | 首次访问、全新浏览器上下文 | 加载器先可见，角色和背景完整后放行；没有破图、空画板或提前倒计时 |
| A02 | 拦住所有关卡图片请求 | 开始/继续/拖放及快捷键均不可推进；快照、波次与学习事件不变化 |
| A03 | 逐个释放图片，最后保留大背景 | N/M 来自真实完成数；背景未就绪不放行；解码/绘制未完成不显示成功 |
| A04 | 放慢 JS/CSS、模块请求失败 | 有独立于大素材的提示和重新打开入口，不能永远白屏 |
| A05 | 角色/背景/道具任一 404、500、返回 HTML | 有限重试与明确失败，返回可用；坏响应不写成功缓存 |
| A06 | 截断文件、摘要错误、缓存损坏 | 仅补相应文件；不存在混用旧哈希内容或全站清理 |
| A07 | 点击重试、多次连续点击 | 已成功文件复用，任务去重；成功后仅一个 Phaser 实例，玩法不重复开始 |
| A08 | 加载中返回、切槽位、切关、浏览器前进后退 | 旧回调无效，当前页面不被覆盖，无幽灵音频或后台战斗 |
| A09 | 热缓存再次进入与浏览器重启后进入 | 文件可复用；解码/场景检查仍执行，不重新完整传输相同素材 |
| A10 | 存储禁用、配额不足、浏览器驱逐 | 能走网络/内存；提示准确；玩家存档和恢复日志未被删除 |
| A11 | 首次无 Worker、Worker 安装失败/等待激活 | 主加载流程仍可用，不能永远等待 Worker |
| A12 | 断网前已认证且当前资源完整/不完整 | 完整时遵循现有续玩；缺失时阻止进入；刷新不绕过登录 |
| A13 | 新版本仅改一张图片 | 该文件地址变化，其他地址不变；仅缺失或变化内容重新传输 |
| A14 | 新版本清单先到、文件未齐/协议未知 | 不切半成品版本，已有版本继续；记录发布错误 |
| A15 | 战斗中发布新版本与 Worker 更新 | 不强制刷新、不换当前纹理；到安全位置保存后才能选择更新 |
| A16 | 两标签页分别使用新旧版本及缓存清理 | 活跃关卡可用，清理不破坏其他页；存档写锁逻辑不变 |
| A17 | 更新时保存失败、云冲突、认证失效 | 遵循现有问题处理，不重载丢状态，不误报为素材失败 |
| A18 | 应用与素材回滚 | 页面、清单和资源匹配；新旧用户进度不被清空 |
| A19 | 声音开启、关闭、系统锁定、读音缺失 | 权限与资源状态分开；必要学习音频缺失不能静默开始；普通音乐失败可玩 |
| A20 | 下一波、特殊敌人、受伤层、结算、图鉴分页 | 首次出现时无必要资源突发缺失；所有可达资源被清单覆盖 |
| A21 | 后台预取与当前关卡同时请求、省流量 | 当前任务优先，并发符合限制；省流量不自动全量下载 |
| A22 | 窄屏、触屏、横竖屏、键盘和读屏 | 不溢出，焦点正确，操作可达，状态有文字说明 |
| A23 | 每个动画触发、播放、结束、连续重试 | 实际运行验证，结束不残留遮罩、不吞点击、不叠播放；不能只看截图 |
| A24 | 游戏减少动态、系统减少动态分别启用 | 即时反馈完整，不依赖 animationend 解锁 |
| A25 | 后台挂起、锁屏恢复、零尺寸宿主、WebGL 丢失 | 冻结与恢复正确；有效绘制前不能继续，不补算战斗时间 |
| A26 | 所有正式发布资源及配置 CDN | 依赖闭包、SHA-256、MIME、CORS、缓存头、404 行为均正确 |
| A27 | 连续切关 20 次与低内存设备 | 无持续资源泄漏、实例累积、明显卡顿；释放正确 |
| A28 | 清理素材缓存、退出/切换账号 | 仅公共资源按规则清理，玩家数据与认证隔离保持正确 |

必须在桌面 Chromium 自动化与真实 iPad Safari 上执行核心入口、音频解锁、缓存复用、断网恢复和动画验收；桌面 WebKit 模拟不能替代真实设备结果。生产冒烟只进行已授权的正常操作，不故意清除玩家数据或破坏线上资源。

测试组合包括单元级依赖/去重/状态机验证、ResourceManager 与 Phaser/React 的集成验证、可控网络端到端验证及部署检查。回归测试必须覆盖原始模式：图片一直未完成时按钮和内部逻辑都不能开始。

## 15. 技术参考

- [Phaser Loader 官方说明](https://docs.phaser.io/phaser/concepts/loader)：加载进度、文件完成与场景生命周期；实际实现需以项目安装的 Phaser 3 版本验证。

- [MDN Cache API](https://developer.mozilla.org/en-US/docs/Web/API/Cache)：应用管理响应缓存的能力与边界；Cache API 不自动遵循 HTTP 缓存过期策略。
- [MDN 浏览器存储配额与驱逐](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)：本地持久缓存可能失败或被清理，不能作为永久可用承诺。



## 当前实现与加载呈现

运行实现位于 `web/src/resources/`，构建入口为 `scripts/garden-resource-build.mjs`；资源字典管理图片/音频，外壳清单记录 HTML/JS/CSS 完整依赖与摘要。运行页面固定自己的发布清单，不用 latest 替换进行中的版本。关卡依赖从学习计划全部三波推导，当前战斗图像使用完整集合，背景按难度选择。体积与摘要以正式构建的 `resource-budget.json` 为准。

加载页和场景等待层使用独立视口布局，手机竖屏、横屏与平板均须完整显示操作；短横屏可滚动。素材等待超过200ms显示加载卡；素材就绪后仅等待账号/存档确认时，使用从任务开始计算的600ms宽限。失败立即显示，已显示卡片在阶段切换时连续接续，不隐藏重播。HTML启动占位以无位移动画的400ms延迟显现，已显示时由React加载卡接续；资源就绪后不播放整页淡入。这些宽限只控制显示，不提前放行游戏。

必要读音失败保持阻塞，普通音乐失败降级。音频上下文中断会暂停；解锁后仍由用户手动继续。家长可管理全量缓存、暂停、检查更新、清理未使用素材与导出诊断。

长期浏览器回归在 `web/e2e/resources.spec.ts` 与 `loading-presentation.spec.ts`；发布校验见部署手册。真实iPad Safari锁屏、缓存驱逐、GPU内存与性能、多设备完整流程仍需专项验收，见[维护待办](../../pinyin-garden.md#待办与验收边界)。
